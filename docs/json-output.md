# Opt-in JSON response mode

`EMU_JSON_OUTPUT=true` switches emutools from tolerant text-tag parsing to a bounded JSON envelope. It requires an upstream that supports `response_format: {"type":"json_object"}`. It is disabled by default; generic OpenAI-compatible backends keep their existing behavior.

This remains **tool emulation**. No native upstream `tools`, `functions`, or native tool-choice definitions are sent. The client's declarations are described in the prompt; validated calls are translated back to the client's Anthropic or OpenAI wire protocol.

## Response contract

```json
{
  "text": "",
  "tool_calls": [
    {"name": "Read", "arguments": {"file_path": "example.txt"}}
  ]
}
```

A final answer has a string `text` and an empty `tool_calls` array. The example tool name and arguments must be replaced by a tool actually declared by the client.

- Responses must decode to the expected complete envelope. With `EMU_SALVAGE=true` (the default), a bounded recovery can remove at most two mismatched closing brackets inside an open container. It cannot add tokens or change literal values. Set `EMU_SALVAGE=false` for strict JSON decoding without this recovery.
- Incomplete envelopes, duplicate keys, non-finite numbers, fabricated result fields, missing names, and non-object arguments are rejected. Unterminated strings are never completed; a truncated peer cannot release an earlier call. After any structural recovery, the same strict JSON and tool-schema validation still applies.
- Optional string IDs copied from history are ignored on output. Native client tool IDs are generated by emutools.
- Tool availability, input schemas, named/required/disabled choices, per-turn limits, and repeat/round guards still apply.
- History is serialized consistently as JSON, including identifiers connecting real tool results to earlier calls.

## Streaming trade-off

The upstream connection and client wire format can still use SSE. However, emutools buffers the **whole JSON envelope** before emitting its text or calls, up to 524,288 characters. This increases first-content latency relative to the default incremental text parser. An incomplete response cannot release even an earlier complete-looking call.

Empty or rejected responses can receive at most three attempts when `EMU_LOOP_RETRY=true`. Once a valid call has been emitted, it is not replayed to repair a rejected peer. Transport failures are not silently retried by this repair loop. Completed-attempt usage is aggregated.

## Generation controls

```bash
export EMU_UPSTREAM_API_KEY=sk-...  # use your own secret; never commit it
EMU_JSON_OUTPUT=true EMU_THINKING=enabled EMU_REASONING_EFFORT=low \
  EMU_PARALLEL=true python3 -m emutools
```

This is an example configuration, **not a universal reliability guarantee**. `EMU_THINKING` accepts `enabled` or `disabled`. `EMU_REASONING_EFFORT` accepts `low`, `medium`, `high`, `xhigh`, or `max`; support and interpretation depend on the provider. Both default to empty, preserving the provider's defaults. The proxy does not automatically translate incoming Anthropic thinking settings into provider-specific controls.

DeepSeek documents both JSON output and a possibility of empty responses. In the live full-stack challenge, non-thinking JSON mode produced both valid batches and whitespace-only/malformed responses. A provider's JSON setting does not justify bypassing local validation or marking an unfinished workflow successful.

## Reproducible checks

```bash
python3 -m unittest discover -s tests -p 'test_structured_output.py' -v
python3 -m unittest discover -s tests -v
python3 -m emutools --selftest
python3 build_single_file.py /tmp/emutools.py
python3 /tmp/emutools.py --selftest
```

Run the offline suites with a clean test environment rather than inheriting production generation settings. The focused tests cover exact string preservation, guarded batching, bounded buffering, malformed envelopes, sync/stream repair, usage aggregation, and no replay after delivered calls or transport failures.
