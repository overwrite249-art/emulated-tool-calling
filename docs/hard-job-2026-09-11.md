# Hard-job test report — 2026-09-11

## Scope

A text-only model that passes a smoke test can still fail a real job. This round drove
**Claude Code 2.1.268** through emutools against **`deepseek-flash`** — a real, cheap,
tool-less DeepSeek model — on a job designed to attack the emulation itself, and fixed
everything that broke. Every bug below was found by running it, not by reading the code.

Reproduce with `scripts/hard_job_smoke.py`:

```bash
export EMU_UPSTREAM_API_KEY=sk-...
python3 scripts/hard_job_smoke.py --cli "$(command -v claude)" \
  --out-dir /tmp/emutools-hard --model deepseek-flash
```

## The job

A disposable fixture holds `SPEC.md`, a buggy `chunker.py`, an empty `payload.py`, a
`test_hard.py` the model must not edit, and a stdio MCP server. The client is given
`Read`, `Edit`, `Bash` restricted to `python3 test_hard.py`, and one MCP tool. To finish it
has to:

1. fix three real bugs — an off-by-one slice, two `str.replace` calls in the wrong order
   so backslash escaping double-escapes, and a width function counting UTF-8 bytes
   instead of characters;
2. call the MCP tool for a release token and store it verbatim (`RT-7f3a91-Ж`);
3. reproduce an adversarial payload **byte for byte** through the emulated protocol: a
   literal `</tool_call>`, a literal `<arg name="file_path">`, DeepSeek's `｜｜DSML｜｜` and
   `｜tool▁calls▁begin｜` markers, nested JSON escapes, `C:\temp\new\files`, Cyrillic, an
   emoji, and `'''` / `"""` / backticks;
4. run the test itself and keep working until it really passes.

A run counts as passed only if **all** of these hold: the client exits 0, an *independent*
test run passes, `test_hard.py`'s SHA-256 is unchanged, the MCP server logged the call, the
transcript contains the real test output, and the client's final result says so. Anything
less is a failure, including a client that says it succeeded.

## What the live runs found

| # | Symptom in the client | Root cause | Fix |
| --- | --- | --- | --- |
| 1 | Every assistant message carried visible `<｜｜DSML｜｜ calls>` garbage | the wrapper stripper only knew the `<tool_calls>` spelling | strip every marker dialect, at any chunk boundary, without touching identical text inside arguments |
| 2 | One guessed tool name ended the whole task, reported as success | a rejected call was streamed to the user as the assistant's answer | re-ask upstream inside the same client turn; an unsalvageable turn becomes a retryable 5xx, never an answer |
| 3 | Three retries produced three identical rejections | the corrective prompt did not say which tools exist | restate the catalogue, add a "did you mean" hint and a correct example for the tool that failed |
| 4 | `{"name":"Read","arguments":{"name":"Read","arguments":{...}}}` rejected forever | doubled call envelope | unwrap envelopes, including one holding a JSON string |
| 5 | `(The model returned an empty response.)` ended the task | an empty sample was forwarded as a finished turn | re-ask; fail retryably if it stays empty |
| 6 | Model wrote "Now I'll fill in payload.py." then a bare `{"name": "Edit", ...}`, and the edit never happened | a bare JSON call was only recognized when it was the *entire* reply | recognize a bare call wherever it starts a line, streamed or batched, holding back an unfinished one instead of leaking it |
| 7 | Bare `{"name": "Write", ...}` became the final answer | bare-call detection required a *registered* tool name | an unregistered name is still a call: it must reach the validator and the corrective retry |
| 8 | After a rejection the model said "Now I'll write payload.py." and stopped | prose with no call was accepted as an answer | a turn that already tried to call keeps trying, then fails retryably |
| 9 | Model wrote only the arguments - `{"command": "...", "description": "..."}` - with no tool name, and the object became the answer | nothing in the reply looked like a call | a nameless object that fits exactly one tool's schema, and no other, is that tool's call |
| 10 | `[loop guard] Skipping a repeated call` ended the task | the repeat limit spoke to the user instead of to the model | tell the model the repeat is pointless and let it break its own loop; the guard text is the last resort that still bounds it |
| 11 | Small/fast model requests failed upstream | `EMU_MODEL_SMALL` defaulted to `deepseek-v4-flash`, which does not exist | default to `deepseek-flash`, as listed by `GET /models` |
| 12 | Half-written call markup - `<arg name="file_path">`, an unclosed `<invoke `, a lone `</tool_call>` - was delivered as the assistant's answer | the parser either found a complete call or found nothing, so a malformed attempt looked like prose | recognize the *attempt*: a reply that clearly tried to emit call markup but cannot be parsed is re-asked, and fails retryably rather than answering |

Two further details mattered as much as the parsing:

- **A stream must not commit before it can succeed.** Both stream writers now hold their
  first event until the turn is known usable, so an unusable turn fails with an HTTP status
  the client retries rather than a truncated 200. A mid-stream failure is still an in-band
  `error` event, which Claude Code retries once as a non-streaming request.
- **Failure has to look like failure.** Any successful assistant message is a finished
  answer to a coding agent. Proxy diagnostics are therefore never delivered that way;
  deliberate policy outcomes (`tool_choice=none`, the repeat limit) still are, because
  there the client asked for prose.

## Client behaviour worth recording

- `claude --bare` exposes only `Bash`, `Edit`, `Read` plus MCP tools. `Write` is dropped
  from `--tools` silently, in every permission mode. The model asks for `Write` anyway, so
  the corrective prompt has to tell it to edit the existing file instead.
- `--tools` is variadic and will swallow a positional prompt; pass the prompt on stdin or
  put another flag after it.
- Under `--permission-mode dontAsk`, a `Bash` command outside the allow-list is denied with
  a message that invites the model to try another tool. Models often then guess a path
  outside the working directory; the first `Read` failure teaches them the real one.

## Results

Offline, on every change: **109 focused regressions** and **203 built-in checks** pass,
from the package and from the generated single file. The 39 regressions added this round
reproduce the bugs above, each at chunk widths 1, 2, 3, 5, 7, 13, 29 and 4096, so no fix
depends on how the upstream happens to split its SSE events.

Live, the job is a real model doing real work and is not deterministic, so it was run in
batches of five, each batch after the fixes that the previous batch's failures demanded:

| Batch | Passed | What the failures were |
| --- | --- | --- |
| baseline | 2 / 5 | bugs 1-5: vendor markers, rejection-as-answer, empty reply |
| after 1-5 | 4 / 5 | bug 6/7: a bare JSON call leaked as prose |
| after 6-8 | 4 / 5 | bug 9: a nameless argument object leaked as prose |
| after 9 | 3 / 5 | bug 12: `<calls in parallel>` and `<arg name=…>` fragments leaked |
| after 10-11 | 4 / 5 | bug 12 again: a lone `</…_call>` fragment leaked |
| final | **5 / 5** | none — including one run with `--parallel` |

Every passing run satisfies all six independent criteria: the client exits 0, the task's
own test suite passes when re-run outside the client, the test file's sha256 is unchanged,
the MCP tool was really called, the transcript contains the real test's success marker, and
the final result contains the job's completion marker.

Total upstream cost of the whole investigation was about **CNY 2.9**, roughly CNY 0.14 per
live run of the job.

## Limits

- One model, one client, one job. Other text-only models write other malformed shapes.
- Argument repair guesses only when the intent is unambiguous: one stray key and one
  missing required key. Two misnamed parameters at once are still rejected.
- The adversarial payload is deliberately near the limit of what a text protocol can carry.
  Raw XML argument form cannot represent its own closing delimiter; JSON is the right
  choice for arbitrary source code, and the job is passed that way.
