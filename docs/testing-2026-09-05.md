Representative coverage:

- UTF-8/DSML split at network byte boundaries; multiline SSE, CRLF and EOF framing.
- The first SSE event arrives over a real TCP connection without waiting for the next
  event or upstream EOF.
- Literal closing tags and vendor markup survive inside JSON and raw arguments.
- Fabricated tool-result continuations and unterminated JSON strings cannot become
  executable calls; bare-JSON calls do not leak as assistant text before tool emission.
- Named/required/disabled tool choices, call caps, nested schema constraints, bounded
  retries, exhausted retries and usage accounting.
- Anthropic/OpenAI streaming failures are errors, not successful stop responses.
- Duplicate Content-Length, Content-Length plus Transfer-Encoding, invalid/truncated
  chunks, trailers, keepalive reuse, request limits, invalid UTF-8/JSON and per-server config.

One existing expectation changed intentionally: it now checks that the upstream stop
sequence follows configuration, rather than assuming closing-tag stops are always on.
`EMU_USE_STOP=false` is the new safe default for file-editing tasks.

## Real-client CI, without paid inference

The CI job installs pinned official binaries and runs the same disposable MCP/file/shell
fixture against `scripts/cli_mock_upstream.py`. Only the model is mocked: the CLI,
HTTP translation, MCP process, file operations and Python test command are real.
This is compatibility coverage, not evidence that a real LLM will choose correct tools.

Claude Code 2.1.261 passes this test. The current OpenCode investigation and its concise
server diagnostics are recorded in the [PR's bot reports](https://github.com/overwrite249-art/emulated-tool-calling/pull/1#issuecomment-5554264749).

The success gate requires a zero client exit status, the real MCP event, the actual
client-executed fixture test output, a final assistant success message and an independent
check of the edited file. CI requires no upstream secret. Same-repository PRs receive
sanitized test summaries; fork PRs do not get a write-capable reporting step.

## OpenCode on the small VPS

OpenCode **1.18.29** installed and reported its version, but two live attempts exited with
SIGKILL before any proxy inference request. Kernel messages explicitly identified the
OpenCode processes as out-of-memory victims. The VPS exposed about **546 MiB RAM**, with
no swap. A low-memory retry did not resolve the startup limit.

A temporary 96 MiB swap file was tried, but the host rejected `swapon` with
`Operation not permitted`; the unused file was removed. No unrelated data was wiped.
The task's own previous Claude installation was removed to make disk space for OpenCode.
**Those failed VPS attempts are not OpenCode + DeepSeek integration passes.**

On the larger GitHub runner, OpenCode reached its own startup code but initially returned
an internal server error before contacting emutools. This is tracked separately from the
VPS memory problem and from the passing protocol/regression tests.

## Known boundaries

- JSON Schema validation is a bounded subset, not full standards compliance.
- Raw XML arguments cannot represent their own closing delimiter unambiguously; JSON is
  preferable for arbitrary source code.
- Multimodal payloads become text placeholders.
- OpenAI Responses/Codex and legacy text Completions are not supported.
- The proxy has no client authentication. Keep it on loopback or put an authenticating
  reverse proxy in front of it. Client-side tool permissions remain important.
